Pico Neo 3 eye tracking in VRChat

Gets the headset's built-in Tobii eye tracking into VRChat, and it keeps working while the headset streams PC VR. No root, no headset app: a small program runs on the headset over adb and sends the data to your PC over Wi-Fi.

Headseteyestream · 90 Hz
Wi-Fi · UDP 7777 →
VRCFaceTracking"Pico Neo 3 Pro Eye" module
OSC →
VRChatyour avatar's eyes

You get

  • Gaze, where you look
  • Blinks and winks, each eye separately
  • About 90 updates per second

You don't get

  • Half-closed eyelids or squints: Pico reports eyes only as open or closed (blinks are smoothed)
  • Separate gaze per eye: both eyes use the combined gaze

Testing this? Start here.

  • You need the zip pico_eye_stream_test.zip (85 KB) from whoever shared this page. Unblock it before extracting (setup step 1) and keep the folder together; the launchers find everything relative to themselves.
  • Use VRCFaceTracking from Steam. The Microsoft Store version doesn't work with this module.
  • The firewall rule (setup step 5) needs PowerShell as Administrator.
  • Run the headset's eye tracking calibration before testing.
  • If anything goes wrong, see Reporting back for what to send.

What you need

Hardware

  • Pico Neo 3 Pro Eye (the Eye model; tested on system 5.11.3, Android 10), with eye tracking switched on in its settings
  • Windows 10 or 11 PC on the same network as the headset (PC wired and headset on the same router's Wi-Fi is fine)
  • A USB-C data cable. Some cables only charge.

Quick setup (recommended)

Extract the zip somewhere permanent, then double-click Set Up Everything.cmd and follow what it says. It downloads adb, checks for Steam, SteamVR, VRCFaceTracking and .NET 10 (and opens the install page for anything missing), adds the firewall rule (click Yes when Windows asks for admin permission), walks you through connecting the headset, installs the VRCFT module and puts a Pico Eye Tracking shortcut on the desktop. If it stops at a step, do that step and run it again; finished steps are skipped.

Then run the headset's eye tracking calibration yourself (it's per person) and go to Every session. PC streaming you set up yourself. The steps below are the same setup by hand.

One-time setup (by hand)

  1. Unpack the folder

    Before extracting the zip, right-click it → Properties → tick Unblock if it's shown → OK. Otherwise Windows may warn about the .cmd files every time. Extract it somewhere permanent, for example C:\pico_eye_stream.

  2. Install adb on the PC

    Download SDK Platform-Tools for Windows from developer.android.com and unzip it so you have C:\platform-tools\adb.exe. A platform-tools folder inside pico_eye_stream, or adb on your PATH, works too.

  3. Turn on developer mode in the headset

    • Settings → General → About: click Software Version about 7 times.
    • Settings → Developer: turn on USB debugging.
    • Run the headset's eye tracking calibration. Without it the data comes back invalid.

  4. Connect over USB once

    Plug the headset in with the data cable. In the headset, accept Allow USB debugging? and tick Always allow from this computer. Then check on the PC:

    C:\platform-tools\adb.exe devices

    You should see a line ending in device. If it says unauthorized, accept the prompt in the headset.

  5. Allow VRCFaceTracking through the firewall

    VRCFaceTracking's module process has to receive the headset's packets. Open PowerShell as Administrator and run:

    New-NetFirewallRule -DisplayName "VRCFT Pico Neo 3 eye (UDP 7777)" -Direction Inbound -Program "C:\Program Files (x86)\Steam\steamapps\common\VRCFaceTracking\VRCFaceTracking.ModuleProcess.exe" -Protocol UDP -LocalPort 7777 -Profile Private -Action Allow

    Change the path if Steam lives elsewhere. Your network must be set to Private in Windows.

  6. Install the VRCFaceTracking module

    Close VRCFaceTracking, then double-click Install VRCFT Module.cmd.

    If it lists other eye modules (ETVR, Baballonia, Pico 4), remove or disable them in VRCFaceTracking's Module Registry. VRCFaceTracking gives the eyes to whichever eye module loads first.

  7. Optional: shortcut and voice output

    Make a desktop shortcut to Start Eye Tracking.cmd.

    The start script speaks its result on the default audio output. To send it to your headphones instead, put part of their device name in voice_device.txt, for example Stealth 600.

Every session

  1. Turn on the headset

    If it was rebooted, plug in USB first. adb over Wi-Fi switches off on every reboot.

  2. Double-click Start Eye Tracking.cmd

    It finds the headset, switches adb to Wi-Fi, reads the headset's current IP and starts the sender. It speaks the result, so you can hear it with the headset on. "You can unplug the USB cable" means it's running.

  3. Start streaming and VRCFaceTracking

    Business Streaming or PICO Link, then VRCFaceTracking from Steam.

  4. Start VRChat

    Use an eye-tracked avatar and check in a mirror.

The sender keeps running until the headset turns off. It pauses while the headset sleeps and resumes about 5 seconds after it wakes. Stop Eye Tracking.cmd stops it early.

Troubleshooting

ProblemFix
"ADB was not found"Install Platform-Tools (setup step 1).
"Headset not found" or "Can't reach the headset over Wi-Fi"Plug in USB and run Start again. Look for the Allow USB debugging prompt in the headset.
"The headset is asking for permission"Put the headset on and accept Allow USB debugging, then run Start again.
Windows sees the headset only as an audio deviceUSB debugging is off, or the cable or DisplayPort mode is in the way. Use a plain USB-C data cable without the DP cable.
Module shows in VRCFaceTracking, eyes don't moveFirewall rule missing (setup step 4), or another eye module took the eye slot. On VRCFaceTracking's Output page, look for Tracking initialized via ....
Cameras show "no answer", or the sender log says no new frames while the headset is awakePico's eye service got stuck. Reboot the headset, plug in USB, run Start again.
Eyes shake or jitter, even with strong smoothingAnother program is also sending gaze to VRChat. Most often it's EyeTrackVR (or Baballonia) on its default settings, which sends straight to VRChat's port 9000. Close it. After closing it, switch avatar and back, or the eyelids can stay half-closed at its last value.
Stops after the headset was off your faceNormal. It resumes within about 5 seconds of the headset waking.
VRCFaceTracking crashes on its module pageYou're running the Microsoft Store version 5.x. Use the Steam version.
PC streaming can't find the headsetDisable extra network adapters (VPNs such as Hamachi, second network cards) in ncpa.cpl.

To see what the headset is doing:

C:\platform-tools\adb.exe shell "tail -3 /data/local/tmp/eyestream.log"

90 pkt/s, 2600 valid per 30 seconds means it's tracking. 0 valid means the headset isn't on your face.

Reporting back

If something doesn't work, send these to whoever gave you the folder:

  1. What you did and what happened, or a photo of the Start window.
  2. The headset log: 
    C:\platform-tools\adb.exe shell "cat /data/local/tmp/eyestream.log"
  3. VRCFaceTracking's Output page (copy all), especially the lines with Tracking initialized and Pico.
  4. Headset system version (Settings → General → About) and your streaming app and its version.

Camera route with Baballonia

Experimental Start Eye Tracking + Cameras.cmd also streams the headset's infrared eye camera images (208×200 per eye, about 77 fps), so image-based trackers like Baballonia or EyeTrackVR can estimate smooth eyelids.

  • Left eye http://<headset-ip>:8080/, right eye http://<headset-ip>:8081/. Show Eye Camera Addresses.cmd shows them with Copy buttons and updates Baballonia's saved addresses.
  • In Baballonia: OSC send port 8888, receive port 8889, VRCFT module mode Both, Native VRC Eye Tracking off. Then run its eye calibration.
  • In VRCFaceTracking, only the Baballonia module may claim the eyes. Remove the Pico Neo 3 and ETVR modules.
Know before you use it. Baballonia's models are trained on DIY eye cameras, and results on the Pico's through-the-lens images were weak in testing. The images come from Pico's debug image dump, which writes to the headset's storage; each frame is deleted within milliseconds. Run it only when you use it.

Uninstall

Remove the module (with VRCFaceTracking closed):

powershell -ExecutionPolicy Bypass -File install_vrcft_module.ps1 -Remove

Remove the programs from the headset:

C:\platform-tools\adb.exe shell rm /data/local/tmp/eyestream /data/local/tmp/eyecam /data/local/tmp/eyeprobe

Remove the firewall rule (PowerShell as Administrator):

Remove-NetFirewallRule -DisplayName "VRCFT Pico Neo 3 eye (UDP 7777)"

Building from source

Only needed if you change the code. Prebuilt files ship in headset\ and vrcft\dist\.

Headset programs (Android NDK r27c)

<ndk>\toolchains\llvm\prebuilt\windows-x86_64\bin\aarch64-linux-android29-clang.cmd -O2 -o headset\eyestream headset\eyestream.c -ldl
<ndk>\toolchains\llvm\prebuilt\windows-x86_64\bin\aarch64-linux-android29-clang.cmd -O2 -o headset\eyecam headset\eyecam.c -lm

After rebuilding, delete the old copy on the headset so the start script pushes the new one.

VRCFaceTracking module (.NET 10 SDK)

dotnet build vrcft\PicoNeo3EyeModule.csproj -c Release -o vrcft\dist

Then run Install VRCFT Module.cmd. How it works and the data layout are in README.md in the folder.

Unofficial community tool, not made or supported by Pico or Tobii. Test build of 31 October 2026, tested on one Neo 3 Pro Eye (system 5.11.3) with Business Streaming 2.0.0 and VRCFaceTracking 6.0.
